## Open the practice notebook

[Open the research notebook](/practice/research-notebook/). No account or installation is needed. Use made-up notes: this is a small teaching application, with no accounts, cloud storage or cross-device sync. It is available for first learner testing; it is not ContextQB Coach.

Your notes stay in this browser profile on this website. Clearing browser data can remove them. Use **contextqb.com** throughout this exercise. Another browser, device or website address will have a different notebook: even **www.contextqb.com** is a separate address for browser storage. Anyone using this profile can open the notes. The notebook itself sends no note contents to a server and runs no tracking script; the host still receives ordinary page requests.

## Try these four checks

1. **Save something recognizable.** Use “Customer conversation — practice” as the source title and “I want to find the same thought tomorrow” as your note. Select **Save note**. Check the displayed title and note, rather than relying only on the success message.
2. **Come back to it.** Reload the page, or close the tab and reopen the same address in the same browser profile. Are both values still there? Your browser may limit or clear storage, particularly in private browsing.
3. **Keep an independent copy.** Select **Download backup** and find the file in your downloads. Then save a second, different note in the main notebook. The earlier backup will not contain this newer note.
4. **Check recovery without replacing current work.** Select **Open an empty recovery notebook**. In that new tab, choose the downloaded file and select **Restore into this empty notebook**. Check that the first note returns and the second does not. Reload to check it again, then return to the original tab and confirm that both current notes remain. Keep adding notes in the main notebook. Bookmark a recovery notebook if you want to return to that particular check.

Restore refuses to replace notes already in its destination. It also rejects a file that is not a valid notebook backup. These are useful failures: they protect what is already there. The exercise allows up to 1,000 notes and a 2 MB backup. Editing, deleting, shared accounts and automatic backups are outside this small example.

## Connect the observation to your own product

“It said saved” and “I reopened it and the same information was there” are different kinds of evidence. Ask the same question of any important action in the application you want to build.

- [Direct your first feature](/guides/directing-your-first-feature/): describe the useful result and decide what you will check.
- [Test agent-built software](/guides/testing-agent-built-software/): choose checks that could reveal a mistake.
- [Rehearse backup and recovery](/playbooks/rehearse-backup-and-recovery/): test a recovery path without overwriting the current data.
- [Operate a small app](/guides/operating-a-small-app/): decide who notices problems and what they do next.

This browser exercise demonstrates a narrow set of behaviors. Your own product may need accounts, a server, stronger data protection and other checks. Use the [guides in journey order](/guides/) to follow the core path from an idea through launch and operations. Advanced topics are extensions when your project needs them.
